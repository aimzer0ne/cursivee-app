How a cursive generator actually works

No fonts, no images, no server — just a lookup table from one set of characters to another, and a few quirks of history that explain everything odd about the result.

Type “hello” into a cursive generator and you get 𝒽ℯ𝓁𝓁ℴ. It looks like the same word in a different font, but nothing about the font has changed. Every letter has been replaced by a different character — one whose standard shape happens to be script. This page explains where those characters come from, and why that one fact accounts for everything strange about cursive text: the mismatched letters, the missing numbers, the character limits, and the searches that never find you.

Characters, not fonts

Every character a phone can display has a number in Unicode, the standard that keeps text consistent across devices. The plain capital A is U+0041. When you change the font in a word processor, the number stays U+0041 and only the drawing changes — and the drawing stays behind when you copy the text somewhere else.

A cursive generator works one level down. It does not ask for a different drawing of U+0041; it swaps in a different character altogether: 𝒜, the mathematical script capital A, U+1D49C. The app you paste into does not need a font setting, because it has not been asked to style anything. It has been handed a character whose shape is script.

Where the cursive letters come from

In 2001, Unicode 3.1 added a block called Mathematical Alphanumeric Symbols, running from U+1D400 to U+1D7FF. Mathematicians use letter styles as meaning — a bold v is a vector, a script ℒ might name a function, a blackletter 𝔤 a Lie algebra — and encoding the styles as separate characters lets an equation keep its meaning when it is copied between programs.

The block holds thirteen Latin alphabets, each a run of 52 code points: capitals first, then lowercase. A generator only needs to know where each run starts:

To convert a letter, the generator adds its position in the alphabet to the start of the run. Lowercase script b is the 28th character in the script run — 26 capitals, then a, then b — so it lives at U+1D49C + 27 = U+1D4B7: 𝒷. That is the entire trick. Bubbles (Ⓐ), squares (🄰) and wide letters (Ａ) work the same way with runs from other blocks, and the strikethrough and underline styles add a combining mark after each letter instead.

The eleven missing letters

Look closely at the script run and it has holes. U+1D49D, where script capital B should be, is empty. So are the slots for E, F, H, I, L, M and R, and for lowercase e, g and o. Those eleven letters already existed: mathematicians and physicists had been writing ℬ, ℋ and ℒ as symbols for decades, and Unicode had encoded them in the early 1990s in a block called Letterlike Symbols. Rather than encode them twice, the new block left gaps and pointed back to the old characters.

So a generator cannot just add offsets. It needs an exceptions table — when the letter is B, use ℬ (U+212C) instead of the empty slot. The engine behind this site's generator has exactly that line:

ex:{B:"ℬ",E:"ℰ",F:"ℱ",H:"ℋ",I:"ℐ",L:"ℒ",M:"ℳ",R:"ℛ",e:"ℯ",g:"ℊ",o:"ℴ"}

The visible consequence: those eleven letters live in a different block from their neighbors, and a device may draw the two blocks with two different fonts. That is why the light script style sometimes has letters that look like cousins rather than siblings. Fraktur has the same problem with five capitals (ℭ ℌ ℑ ℜ ℨ), double-struck with seven (ℂ ℍ ℕ ℙ ℚ ℝ ℤ), and italic with one: its lowercase h is ℎ, the physicists' Planck constant. Bold script has no gaps at all, which is why it is the most consistent cursive style. The cursive alphabet shows every letter side by side.

Why there are no cursive numbers

The block includes digits in five styles — bold (𝟎𝟏𝟐𝟑), double-struck (𝟘𝟙𝟚𝟛), sans-serif (𝟢𝟣𝟤𝟥), sans-serif bold (𝟬𝟭𝟮𝟯) and monospace (𝟶𝟷𝟸𝟹) — but none in script, italic or Fraktur. Mathematicians had no use for script digits, so none were encoded, and a generator can only leave numbers plain. Accented letters are missing for the same reason: there is no script é anywhere in Unicode.

Why cursive text can count as two characters

Unicode numbers run up to U+10FFFF, but a lot of software stores text as UTF-16, built from 16-bit units that only reach U+FFFF. Anything above that — emoji, and the whole mathematical alphanumeric block — is stored as a surrogate pair of two units. A plain letter takes one unit; 𝒜 takes two.

Whether that matters depends on how an app counts. Some count what you see, so 𝒽ℯ𝓁𝓁ℴ is five characters. Others count storage units, and the same word becomes eight: the three letters from the 2001 block take two units each, while ℯ and ℴ, from the older block, take one. On X, characters outside the most common ranges count double toward the limit, and cursive letters are among them. If a bio or post is rejected as too long when it looks short, this is almost always why.

Why search cannot always find cursive text

Search matches characters, and 𝒜 is not A. Unicode does define a fallback — compatibility normalization, usually called NFKC — under which 𝒜, 𝓐, 𝔄 and Ⓐ all fold back to a plain A. Some platforms apply it when they index names and posts, so a cursive display name is still found by an ordinary search. Many do not. The safe assumption is that anything written in cursive is invisible to search, so keep the words you want to be found by — your name, your business, your hashtags — in plain letters.

The same folding explains why some apps seem to undo cursive when you press save: they normalize the field on the way in, and your 𝓷𝓪𝓶𝓮 comes back as name.

Why it looks different on every device

Unicode defines what a character is, not exactly how it looks. Apple, Google, Microsoft and the open-source font projects each drew their own mathematical alphabets, so the same bio has slightly different letterforms on an iPhone, a Pixel and a Windows laptop. If a device has no font containing a character at all, it draws an empty box instead. That is rarer than it used to be, and covered in why fancy text shows up as boxes.

What it costs: accessibility

A screen reader sees characters, not shapes. Some announce 𝒽ℯ𝓁𝓁ℴ as a string of names like “mathematical script small h”; others skip the characters entirely. A plain-text alternative is the only real fix, which is why cursive text works best for decoration and worst for anything people need to understand. Can screen readers read fancy text? goes into detail.

What happens inside this generator

The cursive generator on this site is a few hundred lines of JavaScript that run entirely in your browser. For each style it builds a map from plain letters to their counterparts — the offset runs plus the exceptions table — then rewrites your text one character at a time as you type. Characters with no counterpart, such as digits in the script styles, punctuation and accented letters, pass through untouched. Nothing is sent to a server, which is also why it keeps working offline.

That is all there is to it. The real decisions are which alphabets to include and how to present them; the conversion itself is a lookup table, and Unicode did the hard part in 2001.
